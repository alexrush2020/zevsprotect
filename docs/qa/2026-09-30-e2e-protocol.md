# Протокол E2E-тестирования витрины (L-QA) — 30.09.2026

Основание: КП 10.1 (функциональное тестирование), 10.3 (приёмка). Карточка доски — L-QA.
Тесты — `e2e/*.spec.ts` (Playwright, Chromium), конфиг — `playwright.config.ts`.

## Среда и запуск

- БД — изолированная `zevs_e2e` (PostgreSQL из `docker-compose.yml`, порт 5442): миграции + `npm run seed`
  (65 товаров, 7 категорий, 5 статей, 7 отзывов). Фото товаров с zevsprotect.ru в сид не загружены —
  пустые фото в UI не дефект. Общую БД `zevs` тесты не трогают: `e2e/helpers.ts` отказывается работать,
  если `DATABASE_URL` указывает не на `zevs_e2e`.
- Dev-сервер: `next dev --webpack -p 43140` с `DATABASE_URL=…/zevs_e2e`, отдельным `MEDIA_DIR`,
  выключенными Б24 (`B24_WEBHOOK_URL=`) и SMTP (`SMTP_HOST=` — письма пишутся в консоль сервера).
  Playwright сервер не поднимает — запускается вручную.
- Обёртка владельца (подставляет переменные выше): `node --env-file=<.env> e2e-run.mjs <команда…>`.

```bash
# 1. сервер (фоном; turbopack из worktree не стартует — webpack)
node --env-file=.env e2e-run.mjs npx next dev --webpack -p 43140
# 2. (при необходимости) пересев
node --env-file=.env e2e-run.mjs npm run seed
# 3. тесты
node --env-file=.env e2e-run.mjs npm run test:e2e
```

Тесты независимы и самоочищаются: тестовые данные помечены email `e2e-<время>-<rnd>@example.test`
(заявки и гостевые заказы — также имя `E2E …`), `afterAll` каждого файла удаляет заказы, заявки и клиентов
с маркером. Цепочка «заказ клиента → ЛК → повтор → чужой клиент» — `test.describe.serial` в одном файле.
Лимиты частоты (заявки, заказы, /track) считаются по IP в памяти сервера: прогон ставит свой `x-real-ip`
(`E2E_IP`) только на запросы к нашему серверу, поэтому повторный прогон не упирается в лимиты предыдущего.
Перехваты server action в тестах (подмена цены, снятое согласие) идут через `route.fallback()`.

Наблюдения (не дефекты витрины):
- Лимиты частоты доверяют `x-real-ip`; на проде прокси обязан перезаписывать этот заголовок, иначе клиент
  обходит лимиты подстановкой. Проверить в конфиге прокси (L-DEPLOY).
- При выключенном Б24 заказы/клиенты ставят задачи `b24-sync`, которые копят повторы в `payload_jobs` — ожидаемо
  для dev без вебхука.
- React в dev предупреждает о `<script type="application/ld+json">` при клиентской навигации на страницы с JSON-LD —
  рекомендованный Next способ, на работу не влияет.

## Что не проверено

- Битрикс24 (лиды, сделки, статусы из Б24), обмен с 1С (каталог, выгрузка заказов) — выключены в среде e2e.
- SMTP: реальная доставка писем (заказ, регистрация, сброс пароля) — письма только в консоли dev-сервера;
  ссылка сброса проверена токеном из БД, а не из письма.
- Онлайн-оплата и платёжный сервис (BIZ-4), PDF-счёт как файл (проверен только редирект на /invoice).
- Вход через Яндекс ID (заглушка), вход по телефону/SMS (CONTRA-2).
- Отзывы (C-REV), избранное, уведомления ЛК, чат менеджера, прайс CSV, гид закупщика.
- Браузеры кроме Chromium (Safari/iOS, Firefox), реальные мобильные устройства; только эмуляция ширины.
- Продакшен-сборка (`next build` + `start`), нагрузка, конкурентные заказы (дедуп и номер при гонке покрыты
  unit-тестами `lib/server/orders.test.ts`).
- Истечение сессии и блокировка после неудачных входов.
