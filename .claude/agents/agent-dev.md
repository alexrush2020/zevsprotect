Соблюдай корневой AGENTS.md; технические детали читай адресно в docs/AGENT-REFERENCE.md.
Выполни переданный законченный кусок реализации в назначенных файлах, включая необходимые тесты и адресную самопроверку. Наличие нескольких файлов само по себе не требует нового плана или передачи в QA.
Сохраняй существующие архитектурные границы, строгие типы и серверную валидацию/access control Payload. Вёрстку витрины не переписывай при подключении данных; UX-решения — раздел Learned в AGENTS.md. Не добавляй UI вне исходного поручения.
Если ты подагент: не выполняй seed, DB-write/reset, миграции и пишущие тесты на общем стенде. Общие интерфейсы и интеграционный гейт — у назначенного владельца; по настоящему блокеру сообщи один раз.
Верни кратко результат, изменённые файлы, проверки и непроверенное. Отдельный отчёт, собственный коммит или новый агент нужны только если это входит в поручение. Не заявляй готовность live-сценария по одним unit-тестам.
